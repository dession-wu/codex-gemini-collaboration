# 最小任务记录

小任务可用一份记录；多轮、截图或需要恢复时再用目录。默认当前工作区的.collaboration/{日期}-{项目}-gemini-review或用户指定目录，不覆盖旧任务。不强制所有任务生成全部文件。

```markdown
# {项目与目标}
用户原话：
范围、排除项与已有授权：
路径：直接执行 / 独立提案 / 组件建议 / 修改后复核
阶段：准备 / 已提交等待 / 已得建议 / 实施 / 验证 / 待用户处理 / 完成
源码版本：Git提交及未提交差异摘要，或相关文件哈希
截图时间、平台、实际视口/主题、与源码版本的关系：
本任务对话地址（不含凭据）：
提交材料：ID、文件、覆盖与缺失状态
最近动作：是否已提交、是否已得本轮回复、恢复先核对什么
本次外发范围：按实际会话授权填写，不存凭据

| 条目 | 观察/源码推断/假设 | 证据 | 采纳/不采纳/暂缓及理由 | 验收 |
|---|---|---|---|---|

## 结果
改动与保留项：
已执行检查、实际结果与证据：

阻断、普通建议、待验证：
本地预览/已部署/已提交/已推送（分别有证据才填）：
知识：规则、适用条件、反例；或无需沉淀
```

按需保留brief、原始回复、采纳判断、before/after截图、检查结果、差异或备份。文件名不是证据等级。上线状态需实际部署与访问核对，不从构建成功或模型建议推出。

完成：目标有可见结果、必要检查通过，无未解决可信阻断，外部反馈取得/缺失如实记录。普通建议可留后续候选，不必清零主观意见。

两轮后仍有真实阻断或关键分歧，先给已完成成果，再说明问题、推荐选项及影响；不只问是否继续，不用模型通过隐藏风险。

重复错误优先在对应项目用检查或结构改善；审美经验保留适用条件，不把产品数值推广为全局标准。
